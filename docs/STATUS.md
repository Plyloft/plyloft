# Status

What each version of Plyloft changed, newest first. A new entry goes on top,
as `## vX.Y.Z — headline`, with its bullets under **What.**:
`scripts/release.sh` turns the top entry into the site's changelog draft, and
the `ply:release-notes` skill writes entries the same way every time.

The log starts with the first version released from this repository; the
earlier history stays in the private repository it was exported from.
Published builds and their notes: <https://github.com/MatteoB-adv/ply-releases/releases>.

## v1.178.0 — Plyloft is free for one person and open source: Free and Team only, the account optional

**Why.** The owner's decisions of 2026-11-26, recorded in [ADR 0010](adr/0010-free-for-one-person-open-source.md): everything one person does in Plyloft is free, only a team pays, and the app is MIT licensed in a public repository. Nobody had subscribed to a paid plan, so there is nothing to migrate.

- **Free and Team only.** The Pro plan is retired: no Pro gate (`pro_allowed`, `pro_gate`, `ProFeature`, `release_plan_gate`), no Pro checkout, no Pro → Team switch, no Pro marks, "Get Pro" sheets or tutorial `pro` field. Everything for one person runs on every plan; Team is paid per member and adds the shared GitHub Issues board with claims, the team library, overlap warnings and the pull requests a teammate asks you to review. The Free one-card limit is gone (`plan_gates.rs`, `start_check.rs`, `cardSlotStore`, `planUpgradeStore`, "Pause it and start this one", `kanban_card_put_back_preview`, `PrReview.slot_released`). A stored `Plan::Pro` still reads, as Free; the old auto-fix reasons `"card_slot"` / `"plan_required"` still load (as an unknown reason). `account_checkout` accepts only Team. My library's existing-repository lookup now runs on every plan (a read).
- **The Plyloft account is optional.** No full-window Sign-in screen: Setup's "Plyloft account" step is optional and Setup closes without one; Settings › Plan has *Your plan* and *Plyloft account*. Only a team needs the account. Team actions without an account, or with Team on another computer, refuse with their own words (`Plyloft account needed:`, `Team is on another computer:`, `Choose a computer to use Team.`) and *See your plan*; *Create team* and an already joined team offer *Sign in with GitHub* on the spot.
- **Use Team on this computer and the server contract.** Signing in revokes nobody. With Team, one computer holds it at a time: `account_use_team` → `POST /session/use-team` moves it; the other stays signed in, on Free. Every call sends `X-Plyloft-Team-Choice`; the server's unsigned `team` field (`active` here / elsewhere / nowhere, `teamRole`, `device`) becomes `AccountInfo.team {state, device, teamRepo, role}`, shown only, never a gate; `lastKnownPlan` keeps the offline notices to Team. `TeamAccess` gains `SignedOut`, `TeamElsewhere`, `TeamToChoose`. `account_reclaim` and the "replaced" state are gone: a replaced session is taken back silently (`POST /session/reclaim`) from a server that echoes the header, and the account signs out by itself only for a session the server closed. `account.json` no longer writes `replacedBy` (an older file still loads) and writes `lastKnownPlan` and `team`. A member with a seat whose Team runs on another computer still sees *Give up the seat…*, whose confirmation says the seat is freed on all their computers. The licence server (private, migration 008) gives Team to the only active session of an account that updates from 1.177.1, and answers `410 plan_retired` to the Pro checkout and the switch routes; a 1.177.1 app keeps today's behaviour, and its *Use it here* still takes Team. Release order: the server before the app ([RELEASING](RELEASING.md)).
- **MIT licence and the public repository.** `LICENSE` (MIT), the licence field in the crates and `package.json`, and `scripts/export-public.sh` with its lists, checks (forbidden strings, gitleaks, large files, dangling links and read paths) and the public README, CONTRIBUTING and SECURITY (`docs/ARCHITECTURE.md` describes it). `.github/workflows/release.yml` and `VERSION` are gone; the walk tooling reads its test accounts from a git-ignored `scripts/app-tester/walk.env`.
- **Also.** The user guide, tutorial steps, `LAUNCH_API.md` and `docs/ARCHITECTURE.md` (account, licence, billing, Plan page, persistence) follow the code. No new child process, GitHub write or navigated destination; one persisted-field change (`account.json`: `lastKnownPlan`, `team` added, `replacedBy` no longer written).
- **Verified 2026-11-26 and 27.** `./scripts/ppvp.sh` 11/11; `cargo test --workspace --lib` (6,259 passed); the full vitest (378 files, 4,453 passed); `cargo check --target x86_64-pc-windows-gnu`; the licence server's tests (357), typecheck and build. Migration tests for `account.json`: `replaced_files_of_1_167_to_1_177_load_and_ask_the_server_again`, `files_without_the_new_fields_read_defaults`, `a_card_with_the_old_slot_released_field_still_loads`. On a clean copy of the public export, following its README: `npm ci`, `./scripts/ppvp.sh` 11/11, `npm run test:ui`, `cargo test --workspace --lib`, and `npm run tauri build` up to `Plyloft.app` (the DMG step needs a terminal allowed to automate Finder).
- **Tier 4, walked 2026-11-26 and 27** (app tester, test builds against the staging server; no step failed). Without an account, on a Mac and on Windows: an existing profile opens with no Sign-in screen, on Free; two cards Working at once with no limit notice; a first run closes Setup without an account; *Create a team* asks to sign in. Signed in, one member on a Mac and a Windows PC: a seat ready on no computer, *Use Team on this computer* on one, `Team is on another computer (…)` on the other, then back, cards and the Board usable throughout; sign-out goes to Free with no Sign-in screen.
